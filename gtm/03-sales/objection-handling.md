# Objection Handling

> Respond honestly. Never counter an objection with an invented stat or unbuilt feature.

| Objection | Underlying fear | Response |
|---|---|---|
| "Too expensive." | ROI unclear | Anchor to leakage saved (stock + missed billing). Offer low-cost pilot to prove it. |
| "We use paper and it works." | Change risk | Agree it works *until* it leaks money/time. Show the one-screen journey + pilot with no big-bang switch. |
| "Migrating our data will be painful." | Downtime | Walk through the onboarding/migration playbook; pilot at one location first, no full cutover. |
| "What about our internet going down?" | Connectivity | Be honest about current model; note offline-tolerance on roadmap `[confirm]`. Don't overpromise. |
| "Is our patient data safe?" | Security/trust | Explain RBAC + audit logging (real). Be honest that auth hardening is in progress — do not claim certifications we don't have. |
| "Open-source HMS is free." | Cost | Free license ≠ free to run: self-hosting, IT, no support. We're managed + integrated + supported. |
| "We already have a billing/pharmacy app." | Switching cost | We replace 3–4 tools with one consistent system — show the integration value, not just parity. |
| "Will my staff actually use it?" | Adoption | Role-based simple screens + training; pilot proves daily usability. |
| "You're new / no track record." | Trust | Lead with a pilot + early reference logos as we earn them. Don't fake customers. |

## Principle
Convert objections into **pilots**. The pilot answers most fears with evidence instead of claims.
