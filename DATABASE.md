## Table groups

### Patient & visit

- `patient` — demographic + identity (`gender` CHECK in `Male`/`Female`/`Other`)
- `visit` — `visit_type` CHECK in `OPD`/`Emergency`; `status` CHECK in `waiting`/`seen_by_doctor`/`medicines_dispensed`/`lab_tests_done`/`payment_done`/`completed`/`admitted`/`discharged`
- `visit_status_history` — appended by `update_and_log_visit_status(…)`
- `patient_vitals` — `visit_id` UNIQUE; `blood_group` CHECK against ABO/Rh
- OB/GYN: `menstrual_history`, `obstetric_history` (`patient_id` UNIQUE), `para_details`, `current_pregnancy` (`visit_id` UNIQUE)

### Staff & doctor identity

- `doctor` — `user_code` UNIQUE (`DOCNNN`), `password` (scrypt or legacy plaintext), `employment_status`, lockout fields, `session_version`, `mfa_enabled`
- `staff` — `user_code` UNIQUE (`STFNNN`), same auth shape as `doctor`, plus extended profile: gender, DOB, emergency contact, address, national_id, license_id, department, designation, employment_type, facility_code, branch_code, work_location, reporting_manager_staff_id, staff_tags (jsonb)

### Auth, sessions, RBAC

- `staff_roles` — role definitions (12 active rows)
- `staff_role_assignments` — staff ↔ role mapping
- `staff_permissions`, `staff_permission_policies` (84 rows), `staff_permission_audit` (84 rows) — RBAC v2 policy + change history

## Functions & procedures

### Procedure

```sql
update_and_log_visit_status(
  IN p_visit_id integer,
  IN p_status   varchar,
  IN p_updated_by_doctor integer,
  IN p_updated_by_staff  integer
)
```
Updates `visit.status` and inserts into `visit_status_history` in one transaction. **The authoritative path** for status transitions.

## Views

### `v_medicine_pos`
Joins `medicine` with non-expired `medicine_batch` rows; computes `total_stock_quantity` / `total_stock_sub_quantity` per medicine using window aggregates, and `is_out_of_stock` / `is_low_stock` flags. Backs POS search.

### `v_low_stock_medicines`
Active medicines whose aggregated non-expired stock is at or below `min_stock_level × sub_units_per_unit`. Surfaces `get_stock_display(medicine_id)` for the UI.

### `v_daily_sales_summary`
`pharmacy_sale` rows with `status='Completed'` grouped by date: total_transactions, total_sales, total_discounts, cash_sales, card_sales, prescription_sales, otc_sales.

### `admin_cash_collected_ledger_v1`
Unions cashier `payment` / `reversal` txns with pharmacy sales that have `settlement_channel='pharmacy'` and `settlement_status='settled'`. Source field tags each row as `cashier` or `pharmacy`.

## Notes for editing

- Never bypass the `medicine_transaction` trigger chain when changing stock — the math is enforced there, not in route handlers.
- Always use `update_and_log_visit_status(…)` for visit-status changes so the history table stays consistent.
- When adding columns, regenerate `database/snapshot/` and update this file's table-group section if a whole new module appears.
- The live DB has no custom enums — keep using CHECK constraints for consistency, or migrate the whole pattern in one go.
